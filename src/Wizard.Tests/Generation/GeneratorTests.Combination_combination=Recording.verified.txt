==== interactions

Warning ef-sql-recording [EntityFramework, SqlServer]
Verify.EntityFramework and Verify.SqlServer both record every command EF Core runs: Verify.EntityFramework under the name ef, with the command type and transaction state, and Verify.SqlServer under the name sql. Without a choice here every command appears twice in each snapshot.

Warning external-tool [SqlServer]
SqlServer needs A SQL Server instance: the samples open a connection to a local SQL Server. Selecting LocalDb as well gives each test a database of its own instead.

Info recording-bus [EntityFramework, Http, MicrosoftLogging, SqlServer]
These plugins all append to the same recording, which lands in every snapshot taken while it is running, each entry under its own name: ef, sql, httpCall, activity and log.

// Generated by the Verify wizard: https://verifytests.github.io/Wizard/new?step=output&os=Windows&ide=Rider&cli=Cli&tf=XunitV3&ci=GitHubActions&ext=EntityFramework,Http,MicrosoftLogging,SqlServer&sponsor=Exempt&exempt=OpenSource&until=2027-09
// Delete whatever is not needed.
using System.Runtime.CompilerServices;
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata;

// Everything here runs once, when the test assembly loads, before any test.
public static class ModuleInitializer
{
    [ModuleInitializer]
    public static void Initialize()
    {
        // Verify.Http: requests, responses, headers and content are written as readable snapshots,
        // and calls made while a recording is running are appended under the name httpCall.
        // Called explicitly so it runs before Verify.Flurl, which initializes Verify.Http itself
        // when it has not already run; a later VerifyHttp.Initialize() throws "Already Initialized".
        VerifyHttp.Initialize();

        // Verify.MicrosoftLogging: entries logged while a recording is running are appended to the
        // snapshot under the name log.
        // Called explicitly so it runs before Verify.NServiceBus, which initializes it itself when
        // it has not already run.
        VerifyMicrosoftLogging.Initialize();

        // Verify.SqlServer: schema snapshots stay, but recording is off, because
        // Verify.EntityFramework records the same commands under the name ef, with the command
        // type and the transaction state.
        // This has to run before InitializePlugins(): discovery would otherwise initialize
        // Verify.SqlServer with recording on, and a second Initialize throws "Already Initialized".
        VerifySqlServer.Initialize(recordCommands: false);

        // Verify.EntityFramework: the model is read once here so IgnoreNavigationProperties() can be
        // called without arguments, and so navigation properties stay out of entity snapshots.
        VerifyEntityFramework.Initialize(GetDbModel());

        // Initializes every Verify.* plugin the project references and has not initialized above.
        // Explicit calls come first so their parameters apply: a plugin can only be initialized once.
        VerifierSettings.InitializePlugins();
    }

    // Builds a context against a connection string that is never opened, purely to read the model.
    static IModel GetDbModel()
    {
        var options = new DbContextOptionsBuilder<SampleDbContext>();
        options.UseSqlServer("fake");
        using var data = new SampleDbContext(options.Options);
        return data.Model;
    }
}
